ANNOTATION SCRIPT FOR base.pdf
==============================

Purpose
-------
base.pdf contains no annotations. Annotate it by hand in each program you
want to test, following the list below, then save each result as

    base-<tool>-<version>.pdf        e.g. base-okular-24.08.pdf

Do this in at least two or three different programs. The point is that all
of them get compared against ONE expectation set, so any difference in the
output is a difference in how that program writes annotations.

Ground rules
------------
1. Do not let the tool flatten, optimise, or "print to PDF" the file. That
   converts annotations into page content and destroys the test.
2. Check the tool actually writes annotations INTO the PDF. Some readers
   (Skim, Zotero) keep them in a sidecar by default; find the setting or
   use a different tool.
3. Every target phrase ends with a sentinel like [[E1A]]. ALWAYS include
   the sentinel in the selection. The sentinel is how a test knows which
   annotation it is looking at, and how it detects text bleeding in from a
   neighbouring line.
4. Selections start at the first word given and end at the sentinel's
   closing brackets, inclusive. Nothing before, nothing after.
5. Type comments exactly as written, including accents and punctuation.
   Copy-paste rather than retype.
6. Note the tool name and version in a file next to the PDF. If the tool
   has a choice of highlight colour, use yellow unless told otherwise.

E2 -- wrapping across lines                                    (page 1)
----------------------------------------------------------------------

The first block is five lines long and wraps mid-word: the third line
ends "issuer con-" and the fourth begins "centration". The second block
sits directly underneath it.

E2A   Type:     Highlight
      Select:   the WHOLE first block, from "predicted tracking error"
                through to "[[E2A]]" -- all five lines, in one single
                selection (drag from start to end; do not make five
                separate highlights).
      Comment:  Five lines, one hyphenated break.

E2B   Type:     Highlight
      Select:   the WHOLE second block, from "a directly adjacent
                passage" through to "[[E2B]]".
      Comment:  Adjacent to E2A on purpose.

      NOTE:     These two are deliberately adjacent. If E2A's extracted
                text contains [[E2B]] or vice versa, the extractor's
                vertical band is wrong.
